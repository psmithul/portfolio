Hermes Memory Workspace

Personal software experiment · Jun 2026

I built a Markdown workspace in Obsidian so an assistant could pick up ongoing work with the relevant context already organized.

During the cleanup, I removed 89 duplicated skill copies from nine specialist profiles.

Why put context in a workspace?

When work moves between sessions or between specialist assistants, the useful background can be scattered across notes and conversations. I wanted to make the current state of a project easier to find in one place.

I used Markdown in Obsidian so I could read and edit the same notes the assistant used. The structure is visible in the files, so I can trace where a piece of context came from.

Structuring context

Daily notes hold recent work and decisions. Living notes hold project context that stays relevant after the day ends. Both remain editable in Obsidian.

I separated what happened today from information that should still make sense later. A daily note can hold the latest decision and the immediate state of the work. A living note can hold the context someone needs to understand that decision when they return to the project.

I used that distinction to decide where an update belonged. A temporary development could stay in the daily record, while a decision that changes the project could be kept with the project’s longer-lived notes.

Simplifying specialist handoffs

I simplified the specialist profiles so each had a clearer role and fewer duplicated instructions to maintain. A profile registry and shared task queue give each handoff a place to record who is taking over and what is pending.

Keeping the handoff with the task gave each progress update one place to live. The specialist’s instructions could then describe the role without carrying the history of individual tasks.

What I learned

Reviewing the duplicate instructions taught me how easy it is to copy context into several places and make it harder to maintain. The cleanup made me look at each piece of information and decide whether it belonged to a specialist’s role, a shared procedure, or a specific project.

Using the registry and task queue together clarified the difference between background and state. A project note explains the work, while the handoff records who is handling it and where they stopped.
