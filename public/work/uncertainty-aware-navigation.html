Uncertainty-Aware Navigation for an Indoor Mobile Robot

Differential-drive simulation project · Sep — Dec 2025

I built a differential-drive simulator to see how an indoor robot behaves when its position estimate becomes unreliable. I used the estimate’s uncertainty to control speed and recovery and compared the behaviour over repeated simulated runs.

Simulation setup

I wanted to keep the map and goal fixed while changing the quality of the observations. A clear route on the map can still send the physical robot too close to a wall if its heading is biased or a wheel slips. Simulation gave me the true path as a reference for those cases.

Planning and sensor errors

I used A* to plan a route and a heading controller to follow it from the estimated position and orientation. I added encoder noise, IMU drift, yaw bias, and wheel slip to the Python simulator. A slipping wheel can turn without moving the robot as far as the encoder suggests, so I kept the simulated motion and the reported sensor reading separate.

Localisation and motion control

An extended Kalman filter combines wheel encoder and IMU measurements and tracks uncertainty in the estimated pose. I passed that uncertainty to the speed and recovery logic. The planner still provides the route. The controller can slow down or try to recover when confidence falls.

Monte Carlo evaluation

I ran repeated trials and compared the estimated pose with the simulator’s true pose. I recorded collisions, recovery events, completion, and time to goal so I could compare speed with the reliability of getting through the route.

Looking at the estimated pose, true path, and controller decision at the same point in a run helped me explain what had happened. Repeating the trials showed how that behaviour varied with noisy observations.

Fixed speed versus adaptive control

I ran the same simulated conditions with a fixed-speed controller and one that slows when the pose estimate becomes uncertain. In the slip runs, the adaptive version finished 22 of 50 trials versus 3 for fixed speed. Collisions fell from 35 to 6. Successful adaptive runs averaged 55.4 seconds, compared with 32.3 seconds for the few fixed-speed runs that finished. Under nominal conditions, both had zero collisions. The fixed controller finished 40 trials and the adaptive controller finished 42, so the extra time bought much less there.

I also revised the simulator after reviewing individual failures. I checked start poses in continuous space, checked the path between simulation steps for corner contacts, and left more room for position error when deciding whether the robot had arrived. In a separate set of seeds, the revised adaptive controller finished 21 slip trials out of 50, up from 10, but recorded eight collisions instead of seven. That made the revision useful without making it a clean win on every measure.
