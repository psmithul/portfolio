Restia

Self-hosted AI workspace · 2026

A self-hosted workspace that brings model chat, projects, study tools, and documents together.

The public workspace grew out of separate web, desktop-style frontend, and Python service experiments.

Why build one workspace?

I wanted a place where a conversation with a model could sit next to the project, files, and tasks it was helping with. Switching between separate tools is easy for one question. It becomes harder to follow what has happened when the work continues across several sessions.

I tried separate web, desktop-style, and Python versions before bringing the pieces together. Each version gave me a different way to think about the interface, the services behind it, and where the work should be stored.

Bringing the workspace together

In the combined workspace, a project can hold its own board and documents. The study area holds goals and focus sessions, while chat is available alongside the work. I kept those views distinct because they answer different questions about the same work: what I am discussing, what has been decided, and what I have actually saved.

I also separated model choice from the layout of the workspace. Restia supports a local model or a hosted provider through the same workspace, so the project and its documents have a place regardless of which model handles a conversation.

Keeping the data close

The workspace is designed for self-hosting. Files and the database stay on the owner’s infrastructure. The published V2 screenshot shows the connection options between installations. GitHub source.

The self-hosted design also shaped how separate installations connect. An owner can share access to a project with another installation, and the project can distinguish between a viewer and an editor. That keeps collaboration tied to the project and the permissions its owner chose.

What I learned

Building the earlier versions separately taught me to decide which parts of the work need to last across sessions. A board, a document, or a study goal has a useful life beyond the chat that helped create it.

Working through connections between installations made data ownership a design decision. I had to think about where the file lives, which installation is serving it, and what the collaborator is allowed to do with it.
